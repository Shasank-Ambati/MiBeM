Numerical methods I: errors, equations and linear algebra

Every simulation code in this curriculum is, at bottom, a collection of numerical algorithms: it solves equations, factorises matrices, integrates functions and differentiates data. Before you use LAMMPS, FiPy or PySCF you should know what these algorithms promise and where they fail, because the failures do not announce themselves: a code that returns a number returns it with all digits printed, whether the digits mean anything or not. This course (Part I of two) covers the numerical tools that do not involve time or space: how computers represent numbers; how to solve a nonlinear equation; how to solve linear systems, dense and sparse, direct and iterative; how to fit and interpolate data; and how to differentiate and integrate numerically. COMP 202 (Part II) builds on it with differential equations, optimisation, eigenvalue problems and the Fourier transform. All programs are in labs/comp-201 and every number on this page was produced by them.

Lecture 1. Floating-point arithmetic, error and conditioning#

How numbers are stored

A real number is stored in a computer as a floating-point number: a sign, an exponent and a fixed number of significant bits (the mantissa), $x=\pm m\times2^{e}$ with the mantissa $m=(1.b_1b_2\ldots b_{52})_2$ in the IEEE 754 double-precision format used by Python’s float and NumPy’s float64: $1$ sign bit, $11$ bits for the exponent and $52$ for the mantissa. Three consequences are all you need.

  1. Most real numbers are not stored exactly. $0.1=(0.000110011\ldots)_2$ has an infinite binary expansion, so the stored value is the nearest representable number. The spacing between neighbouring numbers is proportional to their size: the relative spacing is the machine epsilon $\varepsilon_\mathrm{mach}=2^{-52}=2.2\times10^{-16}$, and a number is rounded with relative error at most $u=\varepsilon_\mathrm{mach}/2=1.1\times10^{-16}$. Every arithmetic operation returns the correctly rounded exact result: $\mathrm{fl}(a\circ b)=(a\circ b)(1+\delta)$ with $|\delta|\le u$ (the standard model of floating-point arithmetic).
  2. The range is finite. The largest number is $1.8\times10^{308}$; beyond that the result is inf (overflow). The smallest normal number is $2.2\times10^{-308}$; below that precision is lost gradually (underflow). Products of many probabilities underflow (use logarithms); exponentials of large arguments overflow (use the log-sum-exp trick).
  3. Single precision (float32, used by GPUs and by some machine-learning potentials) has $\varepsilon_\mathrm{mach}=1.2\times10^{-7}$: about seven decimal digits instead of sixteen.

Rounding errors of $10^{-16}$ would be harmless if they stayed that size; the rest of this lecture is about when they do not.

Absolute and relative error, and condition

If $\hat x$ approximates $x$, the absolute error is $|\hat x-x|$ and the relative error is $|\hat x-x|/|x|$; the relative error is what matters for physical quantities that span many orders of magnitude (a force of $10^{-12}$ N known to $10^{-14}$ N is excellent; a length of $1$ m known to $10^{-14}$ m too). The number of correct significant digits is about $-\log_{10}$ of the relative error.

Two different things can make a computed answer inaccurate, and they must be kept apart. The first belongs to the problem: how strongly the exact answer $f(x)$ changes when the input $x$ is perturbed. For a differentiable function the relative condition number is $$\kappa_f(x)=\left|\frac{x\,f^{\prime}(x)}{f(x)}\right|,$$ so that a relative perturbation $\delta$ of the input changes the output by a relative amount $\kappa\delta$. A problem with $\kappa\gg1$ is ill-conditioned: no algorithm can do better, because even the rounding of the input to $10^{-16}$ already changes the answer by $\kappa\times10^{-16}$. The second belongs to the algorithm: an algorithm is backward stable if the computed result is the exact answer to a slightly perturbed input (relative perturbation of the order of $\varepsilon_\mathrm{mach}$). A backward-stable algorithm applied to a well-conditioned problem gives an accurate answer; applied to an ill-conditioned one it gives an answer whose error is about $\kappa\,\varepsilon_\mathrm{mach}$, and one loses about $\log_{10}\kappa$ digits.

Example: the condition of subtraction

$f(x)=x-1$ near $x=1$. What is its condition number, and how many digits are lost at $x=1.000001$?

$f^{\prime}=1$, so $\kappa=|x\cdot1/(x-1)|=x/|x-1|$. At $x=2$ this is $2$; at $x=1.1$ it is $11$; at $x=1.001$ it is $1001$; at $x=1.000001$ it is $10^6$ (the table above, item 4 of floating.py). The subtraction itself is exact (a result of the Sterbenz lemma when the numbers are close), but its input is not: if $x$ carries a relative error of $10^{-16}$ from an earlier operation, the difference $x-1\approx10^{-6}$ carries a relative error of $10^{-10}$, so six digits are lost. This is cancellation: subtracting two nearly equal numbers cancels the leading digits that were correct and promotes the rounding errors of the trailing ones to leading positions.

Cancellation in practice, and how to avoid it

Cancellation is the only way in which rounding errors become large in ordinary code, and it can almost always be removed by rewriting the formula. The function $f(x)=(1-\cos x)/x^2$ has the limit $1/2$ at $x\to0$. The naive evaluation subtracts two numbers that agree in all leading digits; the identity $1-\cos x=2\sin^2(x/2)$ gives an algebraically equal but numerically stable formula:

                  1e-03   0.4999999583     0.4999999583
                  1e-05   0.5000000414     0.5000000000
                  1e-07   0.4996003611     0.5000000000
                  1e-08   0.0000000000     0.5000000000
                  1e-09   0.0000000000     0.5000000000

At $x=10^{-5}$ the naive formula has already lost eight digits ($0.5000000414$); at $10^{-8}$ the cosine is rounded to exactly $1$ and the result is $0$ instead of $1/2$: a relative error of $100\%$ from an operation that is exact in real arithmetic. The stable formula is accurate everywhere. The same happens in a very common formula, the roots of a quadratic equation. For $x^2-2bx+c=0$ with $b=10^8$ and $c=1$, the roots are $b\pm\sqrt{b^2-c}$; the smaller one, $b-\sqrt{b^2-c}$, is a subtraction of two numbers of size $10^8$ that agree to sixteen digits:

2. quadratic x^2 - 2bx + c = 0 with b = 1e8, c = 1: the small root is c/(2b) ~ 5e-9
               naive  b - sqrt(b^2-c) = 0.000000e+00
               stable c/(b + sqrt(b^2-c)) = 5.000000e-09
               relative error of the naive root = 1.00e+00

The naive root is exactly $0$ (relative error $100\%$); using the product of the roots $x_1x_2=c$, so that the small root is $c/(b+\sqrt{b^2-c})=5\times10^{-9}$, avoids the subtraction altogether. This is the general recipe: find a mathematically equivalent formula in which no two nearly equal numbers are subtracted (rationalise, use an identity, use a series for small arguments, use numpy.expm1 and log1p for $e^x-1$ and $\ln(1+x)$ at small $x$). In simulations the typical victims are: energy differences between two large total energies (the cohesive energy as a small difference of total energies of order $10^3$ eV); small differences between positions of atoms in a large cell; and the Debye integrand at small $x$ (Lecture 7).

Summation

Adding $N$ numbers with a simple loop accumulates rounding errors that grow like $N\varepsilon_\mathrm{mach}$ in the worst case, because the running sum becomes large and each new small term loses its trailing digits. Three better ways exist: pairwise summation (what numpy.sum does: errors grow like $\log N$), compensated (Kahan) summation, and exact summation of rounded partial results (math.fsum). Results for adding $10^7$ copies of $0.1$:

3. summation of 10^7 terms 0.1: exact sum 1 000 000
               plain loop over the first 10^6 terms: 100000.0000013329   (exact 100000)
               np.sum (pairwise)           : 1000000.0000000000
               math.fsum (exact rounding)  : 1000000.0000000000
               float32 loop, first 10^6 terms: 100958.3438   (exact 100000)

The simple double-precision loop has an error of only $1.3\times10^{-9}$ in $10^5$ here, but in single precision the loop over $10^6$ terms gives $100\,958.3$ instead of $100\,000$: a $1\%$ error, because once the accumulator exceeds about $10^5$ its spacing is $0.0078$ and adding $0.1$ is rounded to the nearest multiple of that spacing. The moral for molecular dynamics: accumulate energies, forces and averages in double precision even if the particle positions are stored in single precision (this is what mixed-precision GPU codes do), and accumulate long time averages with a running mean rather than the sum of a billion terms.

Rules to take away
  • Never compare floating-point numbers for equality; compare with a tolerance appropriate to the quantity.
  • Rounding is harmless; cancellation is not. Look for subtractions of nearly equal numbers and rewrite them.
  • Know the condition number of your problem: a result is trustworthy to about $16-\log_{10}\kappa$ digits at best.
  • Do not report more digits than the least accurate input, the method and the statistics justify.
  • Small residual does not mean small error (Lecture 3): a small residual only shows backward stability.

Lecture 2. Solving nonlinear equations#

Most equations that arise in materials modelling have no closed-form solution: the equilibrium compositions of a regular solution, the Fermi level for a given electron count, the lattice constant at which the pressure vanishes, the temperature at which the Gibbs energies of two phases are equal. All are of the form $f(x)=0$ and are solved by iteration: a sequence $x_0,x_1,x_2,\ldots$ that converges to a root $x^\ast$. The quality of an iteration is measured by its order of convergence: the method has order $p$ if the errors $e_k=|x_k-x^\ast|$ satisfy $e_{k+1}\approx C\,e_k^{\,p}$. Order $p=1$ (linear) means the error is multiplied by a constant factor $C<1$ each step (one more correct digit every few steps); $p=2$ (quadratic) means the number of correct digits doubles each step. Our test equation is Wallis’s cubic $f(x)=x^3-2x-5$, whose only real root is $x^\ast=2.094551481542327$ (calculated here with the robust routine scipy.optimize.brentq and used as the reference).

Bisection

If $f$ is continuous and $f(a)f(b)<0$, then the intermediate-value theorem guarantees a root in $[a,b]$. Bisection evaluates $f$ at the midpoint $m$ and keeps the half in which the sign changes, so the interval is halved at every step: the error after $k$ steps is at most $(b-a)/2^{k+1}$, a linear convergence with $C=1/2$, one binary digit per iteration. It cannot fail (provided the initial bracket is valid), needs no derivative, and uses only the sign of $f$, so it is not affected by rounding in $f$ except at the very last digits. To reduce the interval $[2,3]$ below $10^{-12}$ one needs $\lceil\log_2(10^{12})\rceil=40$ halvings. It is slow, but you should always keep it in mind as the method that works when the others do not.

Newton’s method

Replace $f$ near the current guess by its tangent line, $f(x)\approx f(x_k)+f^{\prime}(x_k)(x-x_k)$, and take the zero of the tangent as the next guess: $$x_{k+1}=x_k-\frac{f(x_k)}{f^{\prime}(x_k)}.$$ If $x^\ast$ is a simple root ($f^{\prime}(x^\ast)\ne0$), a Taylor expansion about $x^\ast$ gives $e_{k+1}\approx\dfrac{f^{\prime\prime}(x^\ast)}{2f^{\prime}(x^\ast)}\,e_k^{\,2}$: the convergence is quadratic. It is a local result: the method converges if $x_0$ is close enough, and may do anything otherwise. In more variables, $\mathbf x_{k+1}=\mathbf x_k-J^{-1}\mathbf f(\mathbf x_k)$ with $J$ the Jacobian matrix, which requires the solution of a linear system at every step (Lecture 3); this is how nonlinear finite-element and implicit time-stepping problems are solved.

The secant method

When $f^{\prime}$ is not available or costly, replace it by the slope of the line through the last two points: $x_{k+1}=x_k-f(x_k)\dfrac{x_k-x_{k-1}}{f(x_k)-f(x_{k-1})}$. The convergence order is the golden ratio $p=(1+\sqrt5)/2=1.618$ (superlinear), but each step costs only one function evaluation, so in terms of cost per digit it is as good as Newton when $f^{\prime}$ costs as much as $f$. Brent’s method combines bisection (safety), secant and inverse quadratic interpolation (speed): it keeps a bracket so it cannot fail, and converges superlinearly when the function is smooth. It is what scipy.optimize.brentq (bracketed) and scipy.optimize.root_scalar use, and it is the right default for a scalar equation. The program below implements the first three methods and prints the iterations:

"""Root finding: bisection, Newton, secant, fixed point, Brent; and a materials example."""
            import numpy as np
            from scipy.optimize import brentq, newton

            def bisect(f, a, b, tol=1e-12):
                fa = f(a); n = 0; hist = []
                while b - a > tol:
                    m = 0.5 * (a + b); fm = f(m); n += 1
                    if fa * fm <= 0: b = m
                    else: a, fa = m, fm
                    hist.append(m)
                return 0.5 * (a + b), n, hist

            def newton_it(f, df, x, tol=1e-14, maxit=50):
                hist = [x]
                for _ in range(maxit):
                    dx = f(x) / df(x); x -= dx; hist.append(x)
                    if abs(dx) < tol: break
                return x, hist

            def secant(f, x0, x1, tol=1e-14, maxit=50):
                hist = [x0, x1]
                for _ in range(maxit):
                    f0, f1 = f(x0), f(x1)
                    if f1 == f0: break
                    x0, x1 = x1, x1 - f1 * (x1 - x0) / (f1 - f0); hist.append(x1)
                    if abs(x1 - x0) < tol: break
                return x1, hist

              double root: error ratio e_(k+1)/e_k = 0.514, 0.502 -> linear (1/2), not quadratic; 52 iterations

Three ways to fail, all of which occur in real simulations.

  1. A bad start. For $f(x)=\sqrt[3]{x}$ the Newton step is $x_{k+1}=x_k-3x_k=-2x_k$: each iteration doubles the distance from the root and changes the sign. A smooth function can send the iteration far away when $f^{\prime}$ is small.
  2. A multiple root. For $f(x)=(x-1)^2(x+2)$ the root $x=1$ has $f^{\prime}=0$: the convergence is only linear with the ratio $e_{k+1}/e_k=1/2$ (measured $0.514$, $0.502$) and $52$ iterations are needed for double precision. A root of multiplicity $m$ has ratio $(m-1)/m$; a remedy is $x_{k+1}=x_k-mf/f^{\prime}$ if $m$ is known. Multiple roots are also very ill-conditioned: a perturbation of size $\delta$ of $f$ moves a double root by $\sqrt\delta$, so a root known to $10^{-8}$ is the best one can expect from double precision.
  3. Wandering. From $x_0=0$ on Wallis’s cubic (where $f^{\prime}(0)=-2$ points away from the root) the iterates jump around ($0$, $-2.5$, $-1.57$, $-0.50$, $-3.82$, $\ldots$) before they may or may not find the root: the basin of attraction of a root of Newton’s method can have a fractal boundary.

The standard robust strategy is therefore: bracket the root, use bisection steps or a hybrid method like Brent’s to get close, and let the fast local method finish; and stop on both a small step $|x_{k+1}-x_k|$ and a small residual $|f(x_k)|$, with tolerances chosen from the scale of the problem.

Example: the miscibility gap of a regular solution

Lecture 3. Dense linear systems: elimination, pivoting and conditioning#

The linear system $A\mathbf x=\mathbf b$ is the workhorse of numerical simulation: every implicit time step, every Newton iteration, every finite-element or finite-difference solve, every fit of data to a linear model leads to it. For a general (dense) $n\times n$ matrix the standard method is Gaussian elimination, organised as the LU factorisation $A=LU$ with $L$ unit lower triangular and $U$ upper triangular. Elimination subtracts multiples of row $k$ from the rows below it to create zeros below the diagonal; the multipliers are collected in $L$. Once $A=LU$ is known, $A\mathbf x=\mathbf b$ is solved in two cheap triangular steps: forward substitution $L\mathbf y=\mathbf b$ and back substitution $U\mathbf x=\mathbf y$, each costing $n^2$ operations. The factorisation itself costs $\tfrac23n^3$ operations, so it is worth keeping when several right-hand sides share the same matrix (the usual situation in time stepping).

Example: LU by hand

$A=\begin{pmatrix}2&1&1\\4&3&3\\8&7&9\end{pmatrix}$, $\mathbf b=(4,10,24)^T$.

Eliminate column 1: the multipliers are $4/2=2$ and $8/2=4$; the rows become $(0,1,1)$ and $(0,3,5)$. Eliminate column 2: the multiplier is $3/1=3$; the last row becomes $(0,0,2)$. Hence $L=\begin{pmatrix}1&0&0\\2&1&0\\4&3&1\end{pmatrix}$, $U=\begin{pmatrix}2&1&1\\0&1&1\\0&0&2\end{pmatrix}$, and one checks $LU=A$. Forward substitution: $y_1=4$, $y_2=10-2\cdot4=2$, $y_3=24-4\cdot4-3\cdot2=2$. Back substitution: $x_3=2/2=1$, $x_2=2-1=1$, $x_1=(4-1-1)/2=1$. The solution is $\mathbf x=(1,1,1)^T$ (indeed $\mathbf b=A(1,1,1)^T$). The factorisation took $\tfrac23\cdot27=18$ operations in this order of counting; for $n=10^4$ it takes $6.7\times10^{11}$, about a minute on one core and a few seconds on a multicore BLAS.

Pivoting

The elimination divides by the pivot $a_{kk}$. If a pivot is zero the method breaks down; if it is merely small, the multipliers are huge and rounding errors are amplified catastrophically. The cure is partial pivoting: at step $k$ exchange rows so that the entry of largest magnitude in column $k$ (on or below the diagonal) becomes the pivot. The result is $PA=LU$ with a permutation matrix $P$, all multipliers have magnitude $\le1$, and the algorithm is, in practice, backward stable (the theoretical worst-case growth factor $2^{n-1}$ is never seen in applications). This is what LAPACK’s gesv does, hence numpy.linalg.solve and scipy.linalg.solve. The program below implements elimination without pivoting and compares:

"""Dense linear systems: LU with pivoting, conditioning, residual vs error, least squares."""
            import numpy as np, scipy.linalg as sla, time

            def lu_nopivot(A):
                A = A.astype(float).copy(); n = len(A)
                for k in range(n - 1):
                    A[k+1:, k] /= A[k, k]
                    A[k+1:, k+1:] -= np.outer(A[k+1:, k], A[k, k+1:])
                return A                            # L (unit lower) and U packed together

            def solve_packed(LU, b):
                n = len(b); y = b.astype(float).copy()
                for i in range(n): y[i] -= LU[i, :i] @ y[:i]
                for i in range(n - 1, -1, -1): y[i] = (y[i] - LU[i, i+1:] @ y[i+1:]) / LU[i, i]
                return y

Residual versus error: what the condition number does

How accurate is the computed solution $\hat{\mathbf x}$? Two quantities measure it: the residual $\mathbf r=\mathbf b-A\hat{\mathbf x}$, which can be computed, and the error $\hat{\mathbf x}-\mathbf x$, which cannot. A backward-stable solver makes the relative residual $\|\mathbf r\|/(\|A\|\|\hat{\mathbf x}\|)\sim10^{-16}$ always, but the error is bounded only by $$\frac{\|\hat{\mathbf x}-\mathbf x\|}{\|\mathbf x\|}\le\kappa(A)\,\frac{\|\mathbf r\|}{\|\mathbf b\|},\qquad\kappa(A)=\|A\|\,\|A^{-1}\|=\frac{\sigma_{\max}}{\sigma_{\min}},$$ with $\sigma$ the singular values (MATH 202). A tiny residual therefore says nothing about the accuracy when $\kappa$ is large. The classical test case is the Hilbert matrix $H_{ij}=1/(i+j-1)$, the normal-equations matrix of polynomial fitting on $[0,1]$. We solve $H\mathbf x=H\mathbf 1$, so that the exact answer is a vector of ones:

In practice a condition number above $10^{12}$ means the matrix is numerically singular, and the cure is to change the problem (a better basis, scaling, regularisation), not the solver.

Where large condition numbers come from in simulations

(i) Fitting with a polynomial basis of high degree or with a poorly chosen set of descriptors that are nearly collinear (Lecture 4). (ii) Discretised differential operators: the matrix of the second derivative on a grid with spacing $h$ has $\kappa\sim h^{-2}$, so refining the mesh always worsens the conditioning (Lecture 5). (iii) Basis sets that are nearly linearly dependent (diffuse Gaussians in quantum chemistry give an overlap matrix with $\kappa>10^{10}$). (iv) Materials with very different stiffness or conductivity in different regions (a composite). (v) Mixing units: variables of size $10^{-10}$ (metres) and $10^{10}$ (Pa) in the same matrix; scaling the variables to order one is free and often the best remedy.

Lecture 4. Least squares: QR, SVD and why the normal equations are dangerous#

Data fitting leads to overdetermined systems: $m$ equations for $n<m$ unknowns, $V\mathbf c\approx\mathbf y$ with $V$ an $m\times n$ matrix (for a polynomial fit, the Vandermonde matrix $V_{ij}=x_i^{\,j}$). There is in general no exact solution; the least-squares solution minimises $\|V\mathbf c-\mathbf y\|_2^2$. Setting the gradient to zero gives the normal equations $V^TV\mathbf c=V^T\mathbf y$, an $n\times n$ linear system that can be solved by the methods of Lecture 3. They are the formulas you meet in statistics (MATH 303) and they are numerically dangerous, for a simple reason: $\kappa(V^TV)=\kappa(V)^2$, so a fit that loses $8$ digits in $V$ loses $16$ in $V^TV$.

The stable alternatives use orthogonal transformations, which do not amplify errors:

  • QR factorisation. Write $V=QR$ with $Q$ having orthonormal columns ($Q^TQ=I$) and $R$ upper triangular (computed by Householder reflections, the same cost order as LU, $2mn^2$). Then $\|V\mathbf c-\mathbf y\|=\|R\mathbf c-Q^T\mathbf y\|$ plus a constant, and the solution is obtained by back substitution $R\mathbf c=Q^T\mathbf y$. The condition number involved is $\kappa(R)=\kappa(V)$, not its square.
  • Singular value decomposition. $V=U\Sigma W^T$ (MATH 202); the solution is $\mathbf c=W\Sigma^{-1}U^T\mathbf y$ (the pseudo-inverse). It costs more (a factor of a few) but it exposes the rank: singular values below a threshold are set to zero, which gives the minimum-norm solution of rank-deficient or nearly rank-deficient problems and is the tool for regularisation. numpy.linalg.lstsq uses the SVD.

Practical rules for fitting
  • Use numpy.linalg.lstsq, scipy.linalg.lstsq or numpy.polynomial classes (which use scaled bases), not inv(A.T @ A).
  • Shift and scale $x$ to $[-1,1]$ and use orthogonal polynomials (Chebyshev, Legendre) rather than monomials when the degree exceeds about $5$.
  • Look at the singular values of the design matrix: a gap or a continuous decay to $10^{-12}$ of the largest means that some combinations of parameters are not determined by the data.
  • With noisy data, add regularisation (ridge regression: minimise $\|V\mathbf c-\mathbf y\|^2+\lambda\|\mathbf c\|^2$), which damps the small singular values and is the basis of the regression methods in CMS 507.

Lecture 5. Sparse matrices and iterative solvers#

The matrices of simulation are rarely dense. Discretise a differential equation on a grid and each equation involves only the neighbours of a grid point; model a crystal with a short-range potential and each atom interacts with a few dozen others; the matrix of the finite-element method has a few tens of non-zero entries per row. Such a matrix is sparse: it stores and processes only the non-zero entries. The prototype is the one-dimensional model of steady diffusion, $-u^{\prime\prime}=f$ on a grid of $n$ points with spacing $h$ (the second derivative is replaced by $(u_{i-1}-2u_i+u_{i+1})/h^2$, derived in Lecture 7): the matrix has $2$ on the diagonal and $-1$ on the two neighbouring diagonals (tridiagonal), and all other entries are zero. Its condition number grows as $\kappa\approx4n^2/\pi^2$ ($178$ for $n=20$, $10\,505$ for $n=160$): the finer the mesh, the worse the conditioning.

Direct methods that exploit sparsity

The cost and memory of a dense solver, $O(n^3)$ and $O(n^2)$, are wasted on zeros. A banded solver (bandwidth $b$) needs $O(nb^2)$ operations; for a tridiagonal matrix, $O(n)$. General sparse LU (SuperLU, UMFPACK, PARDISO, used by scipy.sparse.linalg.spsolve and splu) permutes rows and columns first to limit fill-in, the new non-zeros created during elimination. Iterative methods: Jacobi, Gauss–Seidel and conjugate gradients

An iterative method starts from a guess and improves it using only matrix–vector products $A\mathbf v$, which for a sparse matrix cost $O(n)$. Split $A=D+L+U$ into diagonal, strictly lower and strictly upper parts. The Jacobi iteration solves the equations using the old values of all neighbours, $\mathbf x^{(k+1)}=D^{-1}(\mathbf b-(L+U)\mathbf x^{(k)})$; Gauss–Seidel uses the new values as soon as they are available, $\mathbf x^{(k+1)}=(D+L)^{-1}(\mathbf b-U\mathbf x^{(k)})$. Both are of the form $\mathbf x^{(k+1)}=G\mathbf x^{(k)}+\mathbf c$ and converge for any start if and only if the spectral radius $\rho(G)<1$; the error is reduced by a factor $\rho$ per iteration. For the Poisson matrix, $\rho_\mathrm{Jacobi}=\cos(\pi/(n+1))\approx1-\pi^2/(2n^2)$ and $\rho_\mathrm{GS}=\rho_\mathrm{Jacobi}^2$: the iteration needs $O(n^2)$ steps and, in the simple form, Gauss–Seidel needs half as many as Jacobi.

The conjugate-gradient method (CG, Hestenes and Stiefel 1952) is for symmetric positive-definite $A$. It is based on the observation that solving $A\mathbf x=\mathbf b$ is equivalent to minimising the energy $\tfrac12\mathbf x^TA\mathbf x-\mathbf b^T\mathbf x$, and it chooses at each step the best vector in the Krylov subspace $\mathrm{span}\{\mathbf r_0,A\mathbf r_0,\dots,A^{k-1}\mathbf r_0\}$. In exact arithmetic it terminates in at most $n$ steps; in practice it is used as an iterative method, stopped when the residual is small, with an error reduction of about $(\sqrt\kappa-1)/(\sqrt\kappa+1)$ per step: the number of iterations grows as $\sqrt\kappa$ rather than $\kappa$. Iteration counts to reduce the relative residual to $10^{-8}$ for the one-dimensional matrix:

                d = A.diagonal(); R = A - sp.diags(d); x = np.zeros_like(b)

                    if np.linalg.norm(A @ x - b) < tol * np.linalg.norm(b): return x, k + 1
                return x, maxit

Preconditioning, and a pitfall

The count of CG iterations can be reduced greatly by solving the transformed system $M^{-1}A\mathbf x=M^{-1}\mathbf b$, where the preconditioner $M\approx A$ is cheap to invert and makes the condition number of $M^{-1}A$ small: incomplete factorisations (ILU, incomplete Cholesky), algebraic multigrid, domain decomposition. A method matched to the problem (multigrid for Poisson-type problems) needs a number of iterations independent of $n$ and gives total cost $O(n)$, the theoretical optimum. There is a trap: CG requires a symmetric positive-definite preconditioner. When we used the non-symmetric incomplete LU factorisation of SciPy (spilu) as the preconditioner for CG on the $50\times50$ problem above, the iteration did not converge in $100\,000$ steps, while plain CG needed $93$. For non-symmetric preconditioners use a method for non-symmetric systems such as GMRES or BiCGSTAB (scipy.sparse.linalg.gmres, bicgstab), and for non-symmetric matrices in general. We have not benchmarked preconditioned solvers in this course.

Lecture 6. Interpolation and splines#

Given values $y_i=f(x_i)$ at the points $x_0<\dots<x_n$, interpolation constructs a function that passes through all points, and uses it to estimate values in between. In simulation it appears when a potential is tabulated (EAM potentials in LAMMPS are distributed as tables of $\phi(r)$, $\rho(r)$ and $F(\rho)$ at a few thousand points, and the code interpolates between them with cubic splines), when data from different runs must be put on the same grid, when an equation-of-state curve is drawn through energies at a few volumes, and inside most numerical algorithms. The unique polynomial of degree $\le n$ through $n+1$ points is the Lagrange interpolant $p(x)=\sum_jy_j\ell_j(x)$ with $\ell_j(x)=\prod_{m\ne j}(x-x_m)/(x_j-x_m)$, and its error is $$f(x)-p(x)=\frac{f^{(n+1)}(\xi)}{(n+1)!}\prod_{i=0}^n(x-x_i)$$ for some $\xi$ in the interval. There are two ways to make the error small: make $f^{(n+1)}$ small (a property of the function, which we cannot choose), or choose the nodes $x_i$ to make the polynomial $\prod(x-x_i)$ small. The first is not under our control; the second is, and it turns out to matter enormously.

Splines

A cubic spline is a function that is a cubic polynomial on each interval $[x_i,x_{i+1}]$ and has continuous first and second derivatives at the nodes. The $4n$ coefficients on $n$ intervals are fixed by the $2n$ interpolation conditions, the $2(n-1)$ continuity conditions on $s^{\prime}$ and $s^{\prime\prime}$, and two boundary conditions (natural, $s^{\prime\prime}=0$; or “not-a-knot”; or periodic). Finding the coefficients requires solving a tridiagonal linear system (Lecture 5), so the cost is $O(n)$. The interpolation error is $O(h^4)$ where $h$ is the spacing, for any set of equispaced nodes, with no instability: the table above shows that the spline through the Runge function converges ($0.32$, $0.056$, $0.0069$, $\dots$, $2.8\times10^{-4}$ for $41$ nodes) steadily instead of diverging. Interpolation is not fitting

An interpolant passes exactly through the data; if the data have noise, it reproduces the noise. Fifteen points of $\sin2\pi x$ with random errors of $0.1$ (interp.py, last part) were fitted by the degree-14 interpolating polynomial and by a degree-5 least-squares fit:

               max |interpolating polynomial - truth| = 5.258   max |degree-5 least-squares fit - truth| = 0.055

The interpolating polynomial is wrong by up to $5.3$ somewhere in the interval (more than five times the amplitude of the signal) while the least-squares fit is wrong by at most $0.055$, below the noise level. When the data are noisy, fit a model with fewer parameters than data (Lecture 4); when they are exact (a table, a function you can evaluate) interpolate. Extrapolation, evaluating outside the data range, is a different and more dangerous matter: polynomials and splines diverge quickly outside the range, so never extrapolate beyond what the physical model justifies.

Lecture 7. Numerical differentiation and integration#

Finite differences and the two kinds of error

The derivative is a limit, $f^{\prime}(x)=\lim_{h\to0}[f(x+h)-f(x)]/h$, and the obvious numerical approximation is to use a small but finite $h$. A Taylor expansion shows the error. The forward difference $[f(x+h)-f(x)]/h=f^{\prime}+\tfrac12hf^{\prime\prime}+\dots$ has a truncation error proportional to $h$ (first order). The central difference $[f(x+h)-f(x-h)]/(2h)=f^{\prime}+\tfrac16h^2f^{\prime\prime\prime}+\dots$ is second order, and the five-point formula $[-f(x+2h)+8f(x+h)-8f(x-h)+f(x-2h)]/(12h)$ is fourth order, with the error $\tfrac1{30}h^4f^{(5)}$. Making $h$ smaller reduces the truncation error, but the numerator is a difference of nearly equal numbers (Lecture 1) and each function value carries a rounding error of size $\varepsilon\,|f|$: the rounding error of the difference quotient is about $\varepsilon|f|/h$ and grows as $h$ decreases. The total error $E(h)\approx Ch^p+\varepsilon|f|/h$ is smallest at $h_\mathrm{opt}\sim\varepsilon^{1/(p+1)}$, giving a best error $\sim\varepsilon^{p/(p+1)}$: $\varepsilon^{1/2}=1.5\times10^{-8}$ for the forward difference, $\varepsilon^{2/3}=3.7\times10^{-11}$ for the central difference and $\varepsilon^{4/5}=3.0\times10^{-13}$ for the fourth-order formula. Higher order allows a larger $h$ and a smaller final error, but never an error as small as $\varepsilon$. The experiment, for $f=\mathrm e^x$ at $x=1$:

Noisy data. Differentiating measured or simulated data amplifies noise by a factor $\sim1/h$: a noise $\sigma$ on each value becomes $\sigma\sqrt2/h$ on the difference quotient. Smooth first (fit a spline or a local polynomial: the Savitzky–Golay filter scipy.signal.savgol_filter with deriv=1), or avoid differentiation (integrate by parts, use the integral form of the equation).

Numerical integration (quadrature)

Quadrature approximates $\int_a^bf(x)\,\mathrm dx\approx\sum_iw_if(x_i)$. The idea of the composite rules is to replace $f$ on each subinterval by a polynomial and integrate the polynomial exactly. The trapezoidal rule (linear pieces) has error $O(h^2)$; Simpson’s rule (quadratic pieces, weights $\tfrac h3(1, 4, 2, 4,\dots,4, 1)$) has error $O(h^4)$. Gauss–Legendre quadrature chooses the nodes as well as the weights ($m$ nodes, the roots of the Legendre polynomial $P_m$) to integrate exactly all polynomials of degree up to $2m-1$: for a smooth integrand the error decreases exponentially with $m$. For $\int_0^1\mathrm e^x\,\mathrm dx=\mathrm e-1$:

Singularities, and what to use in practice

The integral $\int_0^1x^{-1/2}\,\mathrm dx=2$ has an integrable singularity at the origin. The midpoint rule is the only simple rule that works (it never evaluates at $x=0$), and it converges as $h^{1/2}$: the errors $0.191$, $0.0605$, $0.0191$, $0.00605$ fall by $\sqrt{10}$ per factor of $10$ in $n$, and to reach $10^{-6}$ one would need $n\approx(0.605/10^{-6})^2=3.7\times10^{11}$ points. The remedy is to change variables. With $x=t^2$, $\mathrm dx=2t\,\mathrm dt$ the integrand becomes the constant $2$ and every rule is exact; adaptive library routines such as scipy.integrate.quad (QUADPACK, adaptive Gauss–Kronrod with extrapolation) find the answer $2.000000000000$ with an error estimate of $5.8\times10^{-15}$ unaided. In practice use scipy.integrate.quad for one-dimensional integrals of a function you can evaluate (and look at the error estimate it returns), the composite Simpson rule or the trapezoidal rule (scipy.integrate.simpson, numpy.trapezoid) for tabulated data, and Monte Carlo (CMS 503) when the dimension is more than about five, since grid rules need $m^d$ points in $d$ dimensions while the Monte Carlo error falls as $N^{-1/2}$ independently of $d$. One special case deserves a remark: for a periodic smooth integrand the trapezoidal rule is exponentially accurate (it is the discrete Fourier transform, Lecture 7 of COMP 202) and is the best rule; this is why the Brillouin-zone integrals of DFT use uniform k-point meshes (LAB 501).

Example: the Debye heat capacity

The Debye model gives the lattice heat capacity of a solid, $C_V/(3Nk_B)=3(T/\theta_D)^3\int_0^{\theta_D/T}\dfrac{x^4\mathrm e^x}{(\mathrm e^x-1)^2}\,\mathrm dx$, where $\theta_D$ is the Debye temperature. Evaluate it numerically for $T/\theta_D$ from $0.05$ to $2$ and check the limits.

The integrand has the form $x^4\mathrm e^x/(\mathrm e^x-1)^2$, which near $x=0$ is a ratio of two small numbers and suffers from cancellation (Lecture 1): for $x<10^{-8}$ the program uses its limit $x^2$ and elsewhere writes the denominator as numpy.expm1(x)**2, which is accurate for small $x$. The upper limit $\theta_D/T$ is as large as $20$; the integrand is smooth and quad handles it:

The low-temperature limit, $C_V/(3Nk_B)\to\tfrac45\pi^4(T/\theta_D)^3=77.93\,(T/\theta_D)^3$, evaluates to $0.009741$ at $T/\theta_D=0.05$, which agrees with the numerical value to all digits printed: a check that the integration is right and that the integral for large upper limit tends to $\int_0^\infty=4\pi^4/15=25.98$ (the numerical $25.975$). Comparing a numerical result with an analytic limit, as here, is the cheapest and most powerful verification there is.

Key takeaways
  • Computers store real numbers as floating-point numbers with a relative rounding error of at most 1.1e-16 (machine epsilon 2.2e-16 in double precision); the damage comes from cancellation and from ill-conditioned problems, not from the individual roundings: (1 - cos x)/x^2 gives 0.5000000414 at x = 1e-5 and exactly 0 at x = 1e-8 where the true value is 0.5, and a stable rewriting 2 sin^2(x/2)/x^2 is right to ten digits.
  • A problem has a condition number kappa and an algorithm loses about log10(kappa) digits; for the function x - 1 near x = 1 the relative condition number is 1/(x - 1), which reaches 1e6 at x = 1.000001, and the same idea applies to linear systems, where the Hilbert matrix of size 12 has condition number 1.6e16 and the solution has an error of 13 percent although the residual is 1e-16.
  • Root finding: bisection gains one bit per step (40 halvings for 1e-12), Newton doubles the number of correct digits (errors 5.8e-4, 1.9e-7, 2.0e-14 for x^3 - 2x - 5 from x0 = 3) but needs a good start and a derivative, and the secant method has order 1.618; Brent's method combines them and is the default in practice.
  • Dense linear systems are solved by LU factorisation with partial pivoting at a cost of (2/3)n^3 operations; without pivoting a matrix with a small leading entry gives x = (0, 1) instead of (1, 1), and least-squares problems should be solved by QR or SVD, not by the normal equations, which square the condition number (the degree-12 fit of exp(x) has an error of 1.1e-7 by the normal equations and 8.9e-16 by QR).
  • Matrices from discretised physics are sparse: a banded or sparse solver needs 0.0003 s for n = 8000 where a dense solver needs 3.9 s; Jacobi and Gauss-Seidel need a number of iterations proportional to n^2 (96 217 and 48 110 for n = 160) whereas conjugate gradients need about n/2 (80), and for the 2D Poisson problem the sparse LU factors have 17.5 million non-zeros for 160 000 unknowns while CG needs 734 iterations.
  • Interpolating with a single high-degree polynomial on equally spaced points diverges (maximum error 1.0e5 with 41 points for 1/(1 + 25 x^2)); Chebyshev nodes (error 2.9e-4) or piecewise cubic splines (error decreasing 16-fold when the spacing is halved) are stable. Differences lose accuracy by rounding for small h (best central-difference error 4.5e-11 at h = 1e-5), whereas Gauss-Legendre quadrature with 5 points integrates exp(x) on [0,1] to 6.5e-13 and the Debye heat capacity is obtained with scipy.integrate.quad.

Quiz 1Basic

Explain why $0.1+0.2\ne0.3$ in floating-point arithmetic and give the correct way to test equality of two computed numbers.

Solution

$0.1$, $0.2$ and $0.3$ have infinite binary expansions and are each stored as the nearest double; the roundings do not cancel, and $0.1+0.2=0.30000000000000004$. Compare with a tolerance: abs(a-b)<=rtol*max(abs(a),abs(b))+atol or numpy.isclose, choosing rtol from the accuracy of the computation (a few times $10^{-16}\kappa$) and atol from the scale of the quantity.

Quiz 2Core

The cohesive energy of a crystal is computed as $E_\mathrm{coh}=E_\mathrm{atom}-E_\mathrm{crystal}/N$, where the total energies are of order $10^3$ eV and $E_\mathrm{coh}\sim4$ eV. If each total energy has a relative error of $10^{-8}$, what is the error of $E_\mathrm{coh}$ and which numerical effect does this illustrate?

Solution

The absolute error of a total energy is $10^3\times10^{-8}=10^{-5}$ eV; the difference has an absolute error of about $10^{-5}$ eV (they add) and a relative error of $10^{-5}/4=2.5\times10^{-6}$, i.e. the condition number of the subtraction is $\sim10^3/4=250$ and about $2.4$ digits are lost. This is cancellation: energy differences of large numbers amplify the relative error of the inputs by the ratio of the sizes. It is the reason total energies must be converged much tighter than the energy differences one wants.

Quiz 3Core

Newton’s method for $f(x)=(x-2)^3$ from $x_0=3$: what is the sequence and what is the order of convergence? How would you accelerate it?

Solution

$f^{\prime}=3(x-2)^2$ so $x_{k+1}=x_k-(x_k-2)/3$: the error $e_k=x_k-2$ is multiplied by $2/3$ each step ($1,0.667,0.444,\dots$): linear convergence, ratio $(m-1)/m=2/3$ for a triple root. With the multiplicity $m=3$ known, $x_{k+1}=x_k-mf/f^{\prime}$ gives the root in one step. Without it, apply Newton to $f/f^{\prime}$ (which has a simple root) or use the Aitken extrapolation of the sequence.

Quiz 4Core

A solver returns a solution with a relative residual of $10^{-15}$ for a matrix with $\kappa=10^{12}$. What do you know about the accuracy of the solution? What would you do next?

Solution

Only that the solver is backward stable. The relative error can be as large as $\kappa\times10^{-15}=10^{-3}$, i.e. only about three digits are certain. Check by perturbing the right-hand side or the matrix slightly and watching the change in the solution; look at the singular values to find the poorly determined combinations; rescale variables; reformulate (a better basis, regularisation) or use higher precision (quad precision, or iterative refinement with a residual computed in higher precision).

Quiz 5Core

You must solve a Poisson problem on a $300^3$ grid ($2.7\times10^7$ unknowns). Compare dense, sparse direct and iterative solvers.

Solution

Dense: $8n^2=5.8\times10^{15}$ bytes ($5.8$ PB): impossible. Sparse direct: fill-in in 3D is severe (the cost scales as $n^2=7\times10^{14}$ operations and the memory as $n^{4/3}$): not feasible on one node. Iterative: each matrix–vector product costs $7n=2\times10^8$ operations; plain CG needs $O(\sqrt\kappa)=O(300)$ iterations, so about $6\times10^{10}$ operations and a few vectors of memory ($\sim1$ GB): feasible in minutes; with a multigrid preconditioner the iteration count is independent of the size. Only the iterative method is practical, and it is what every large-scale PDE and DFT code uses.

Quiz 6Challenge

A colleague interpolates experimental heat-capacity data at 25 temperatures with a degree-24 polynomial and uses the derivative to obtain the entropy. List what is likely to go wrong and what you would recommend.

Solution

(1) Equispaced temperatures give a Lebesgue constant of order $10^6$, so noise of $0.5\%$ becomes errors of order $10^4$ times the data, with oscillations near the ends of the range. (2) Differentiating or integrating an oscillating interpolant is unreliable: the derivative amplifies the oscillations. (3) Extrapolation beyond the data diverges. Recommendation: fit a smooth model with few parameters (the Debye or Einstein form plus electronic terms, or a low-order spline with smoothing), integrate $C_p/T$ with a stable quadrature rule on the data (trapezoid or Simpson) and extrapolate to $0$ K with the physical $T^3$ law; report the error of each step.
